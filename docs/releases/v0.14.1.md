# Cursed Drone 0.14.1

Version 0.14.1 is the first hardening release after the public browser launch. It focuses on session safety, mobile/browser persistence, realtime pitch cost and automated regression barriers rather than adding new synthesis features.

## Session and recovery safety

- every loaded and saved session is sanitized centrally before it reaches the audio engine or disk;
- non-finite and out-of-range master, actor, tuning, Euclidean, modulation and effect values are replaced or clamped;
- a corrupt or incomplete primary `.cdrone` automatically falls back to its previous atomic `.bak` copy;
- backup recovery remains visible in diagnostic output;
- regression tests cover malformed text sessions, save sanitization and backup recovery.

## Mobile and browser persistence

- Android writes the newest autosave immediately when SDL reports backgrounding or termination, and pauses/resumes audio around lifecycle transitions;
- WebAssembly notifies the browser after each successful session write;
- IndexedDB synchronization is debounced, serialized and backed up by a shorter periodic flush plus page visibility events;
- explicit memory-slot saves use the same persistence path as autosave.

## Realtime pitch hardening

Scala pitch quantization now runs at a bounded 16-sample control cadence per active tuning instead of repeating logarithms, powers and degree searches for every audio sample. Disabled tuning still bypasses quantization immediately. The exact Scala calculation and existing `.scl` behavior remain unchanged.

## Regression barriers

- a Playwright smoke workflow launches the real WebAssembly build and verifies navigation with mouse and touch at DPR 1/2, including a Retina letterboxed viewport and a mouse drag gesture;
- shipped runtime changes must advance semantic `VERSION` and include matching release notes;
- the existing Linux, macOS, Android, AArch64 and WebAssembly builds continue to use the same core and session schema.

## Scope deliberately left for later

The release does not implement landscape morphing or restructure the touch frontend. Delay-memory pooling also remains gated on reproducible TrimUI Brick measurements so a risky allocator/runtime rewrite is not shipped without hardware evidence.
